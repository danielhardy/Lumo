## Assessment

- **Editor settled target preserved under concurrent export load:** release-to-settled p95
  `113.068 ms` (traced) / `73.041 ms` (untraced) ≤ `200 ms` — **met**.
- **Interactive responsiveness degrades gracefully rather than collapsing:** interactive p95
  `37.939 ms` / `18.643 ms`. The idle-hardware LUMO-107 warm target (p95 ≤ 33 ms, measured at
  `8.632 ms` idle in LUMO-121) is not met during simultaneous export on every run — expected,
  since the export engine's full-resolution encodes share the GPU — but frames continue to be
  delivered at 22–30 FPS with the editor lane never starved (0 scheduler editor-job drops).
- **Aggregate throughput did not win over the editor:** the batch stayed serial (one full-resolution
  encode at a time), exports were never cancelled by editing, and all 6 items completed.
- The worst frame gap (`1359.838 ms` traced / `593.924 ms` untraced) is concentrated in drag-burst
  coalescing: 44–46 of 60 interactive values were superseded by the latest-wins frame pacer during
  bursts, so presentations cluster at burst boundaries rather than between every pointer tick. This
  is the intended coalescing behaviour, recorded by `dropped_or_coalesced_values`.
- Memory stays bounded during the concurrent run (~122–174 MB resident delta) — consistent with the
  one-resident-full-resolution-result capacity limit documented in `docs/LUMO-113-SCHEDULING.md`.

## Capture-host caveats

- The WindowServer on this capture host reports `presentedTime == 0` for `xctest` drawables (no
  scan-out for the test process's window). The `PreviewSurface.zeroPresentedTimeFallback` capture
  seam (set only by this benchmark) marks such drawables with the same host-time fallback the
  `MetalPresentationBenchmark` procedure (`presentedTime > 0 ? presentedTime : CACurrentMediaTime()`)
  has used for LUMO-118/121 captures; production behaviour is unchanged.
- `interactive_frames_submitted` counts submitted pointer values, not presented frames; superseded
  values are reported as dropped/coalesced, not as zero-latency samples.
- Histogram results are tallied and discarded by the benchmark; correctness is covered by
  `HistogramTests`. The figure reported is the count of completed tallies admitted at `.histogram`
  priority.

The benchmark (`ConcurrentExportEditingBenchmark`) is opt-in via `LUMO_CONCURRENT_CAPTURE=1` and is
driven by `scripts/run-lumo-123-capture.sh`, which mirrors the LUMO-118 capture procedure.
